Event Hub

Plateforme web pour organiser un événement privé (mariage, baptême, anniversaire, fête) : invitations personnalisées avec QR code, RSVP, programme, carte, livre d'or, galerie photo modérée, cagnotte et liste de cadeaux payées via MoneyFusion, tableau de bord et exports pour le traiteur.

Laravel 13PHP 8.4Inertia 2 + Vue 3 + TypeScript Tailwind CSS 3PostgreSQL 16MoneyFusion (FCFA)

1. Présentation

Event Hub est une application monolithique : Laravel gère la logique métier, l'authentification et la base de données, Vue 3 affiche les pages via Inertia.js (pas d'API REST séparée). Deux publics l'utilisent :

L'hôte (organisateur)

Se connecte, crée l'événement, personnalise le thème, gère les invités, le programme, la cagnotte, modère les contributions et exporte les listes.

L'invité

Reçoit un lien personnel (ou un QR code) et accède, sans créer de compte, à son invitation : RSVP, programme, carte, livre d'or, photos, cagnotte.

Le projet a été conçu avec la méthode Spec-Driven Development : les spécifications et la feuille de route sont dans le dossier specs/ (7 phases, toutes terminées).

4. Installation et lancement

Prérequis

  • PHP 8.4 avec les extensions pdo_pgsql, mbstring, gd, zip, dom, xml, fileinfo ; Composer
  • Node.js 20.19 ou plus (testé avec 22) et npm
  • Docker (PostgreSQL et Mailpit)
Package MoneyFusion local composer.json référence le package par un chemin relatif : le dépôt laravel-moneyfusion doit se trouver à côté du projet (../laravel-moneyfusion).

Première installation

  1. Dépendances 
    composer install
npm install
  2. Configuration — .env.example est déjà réglé sur les ports Docker du projet. 
    cp .env.example .env
php artisan key:generate
  3. Infrastructure Docker (PostgreSQL dev sur 5434, PostgreSQL de test sur 5435, Mailpit) 
    docker compose up -d
  4. Base de données (et données de démonstration facultatives) 
    php artisan migrate
php artisan db:seed --class=DemoSeeder
  5. Assets front 
    npm run build

Lancer l'application

Trois processus sont nécessaires (dans trois terminaux) :

php artisan serve --host=127.0.0.1 --port=8000   # application : http://localhost:8000
php artisan queue:work --tries=3                  # envoi des emails et vérification des paiements
npm run dev                                       # facultatif : rechargement à chaud (sinon npm run build)

composer run dev démarre ces processus ensemble (liste visible avec php artisan dev:list).

6. Guide de l'hôte

  1. Se connecter sur /login (ou créer un compte sur /register).
  2. Créer l'événement : « Nouvel événement » → type, titre, adresse personnalisée (optionnelle, sinon générée), date (dans le futur), lieu, message d'accueil, thème. L'aperçu du thème est visible en direct. Le lien public est /e/{adresse}.
  3. Compléter les détails (page « Programme ») : dress code, latitude/longitude pour la carte, étapes de la journée.
  4. Ajouter les invités (page « Invités ») : un par un (nom, email, téléphone, accompagnants maximum) ou par import CSV.
  5. Envoyer les invitations : « Envoyer les invitations (N) » pour tous les invités avec email non encore invités, « Envoyer par email » pour un seul (ou pour renvoyer), « WhatsApp » pour ouvrir WhatsApp avec le message pré-rempli.
  6. Suivre les réponses : le résumé (présents, absents, en attente, personnes attendues) et le détail de chaque invité (accompagnants, régime, chanson, message) sont mis à jour en direct.
  7. Attribuer les tables : saisir la table de chaque invité dans le champ « Table » (enregistré en quittant le champ).
  8. Modérer (page « Modération ») : tout message ou photo d'invité est en attente tant que vous ne l'avez pas publié.
  9. Cagnotte et cadeaux : activer la cagnotte, fixer un objectif, ajouter des cadeaux avec un montant cible.
  10. Préparer le jour J : « Tableau de bord » pour les chiffres et les exports.

Format du fichier CSV d'import

name,email,phone,max_companions
Alice Martin,alice@example.com,+33612345678,2
Bob Durand,bob@example.com,,0

Les colonnes nom, telephone et accompagnants sont aussi acceptées. Les lignes sans nom, avec un email invalide ou déjà présent dans l'événement sont ignorées ; l'import est tout ou rien (transaction). Taille maximale : 1 Mo.

7. Guide de l'invité

L'invité ouvre son lien personnel /i/{jeton} (reçu par email, WhatsApp ou via le QR code). Aucun compte n'est nécessaire : le lien est son identifiant, il ne doit pas être partagé.

Invitation

Titre, compte à rebours, date, lieu, accompagnants autorisés, QR code, programme, dress code, carte.

RSVP

Présent ou absent, accompagnants (jusqu'au maximum fixé), régime, chanson, message. Modifiable à tout moment.

Cagnotte et cadeaux

Choisir la cagnotte générale ou un cadeau, saisir un montant (minimum 100 FCFA) et payer avec MoneyFusion.

Livre d'or et photos

Laisser un message ou partager des photos ; ils apparaissent après validation par l'hôte.

LimiteValeur
Message de livre d'or2 à 1 000 caractères ; 5 messages par invité
PhotoJPEG, PNG ou WebP ; 5 Mo maximum ; 8 000 × 8 000 pixels maximum ; 10 photos par invité (SVG refusé)
Contribution100 à 5 000 000 FCFA, entier ; 3 paiements en cours maximum par heure

8. Paiement MoneyFusion

Les contributions sont payées en FCFA via MoneyFusion (Mobile Money, carte…). L'application utilise le package local simonet85/laravel-moneyfusion. Documentation officielle de l'API : docs.moneyfusion.net.

Déroulement

L'invité saisit un montant→contribution pending créée→paiement créé chez MoneyFusion→redirection vers la page de paiement→retour sur l'invitation + webhook→relecture du statut auprès de MoneyFusion→confirmed / failed
Règle essentielle : jamais de crédit sans vérification serveur MoneyFusion ne signe pas ses notifications (aucun secret ni HMAC documenté) : un webhook ou un paramètre de retour peut être falsifié par quiconque connaît un jeton de paiement. Ils ne servent donc que de signal. Une contribution ne passe à « confirmée » que lorsque l'application relit elle-même le statut sur paiementNotif/{token} et que l'API répond « paid » avec le montant attendu. Une réponse de repli issue de la base locale n'est jamais acceptée.

Statuts d'une contribution

StatutSignificationCompte dans la cagnotte
pendingPaiement créé, pas encore confirmé.Non
confirmedConfirmé par l'API MoneyFusion, montant conforme.Oui
failedÉchec du paiement (ou création impossible).Non
expiredJamais payé après 48 h.Non
mismatchPayé, mais le montant confirmé diffère : « À vérifier » côté hôte.Non

Statuts renvoyés par l'API MoneyFusion : pending, paid, failure, no paid. Un statut inconnu est traité comme « en attente » : il ne peut ni créditer ni faire échouer un paiement.

Trois filets de sécurité

  • Retour du navigateur (/i/{jeton}/donations/{id}/return) : l'invité revient et le statut est relu immédiatement.
  • Webhook (POST /webhooks/moneyfusion) : déclenche un job VerifyContribution (6 tentatives avec délai croissant) ; si MoneyFusion est injoignable, il est rejoué.
  • Réconciliation (contributions:reconcile, toutes les 10 minutes) : rattrape les webhooks perdus et fait expirer les paiements jamais effectués après 48 h (avec une dernière vérification avant expiration).

Budget d'un cadeau

Le contrôle du « reste à financer » est fait sous verrou de base de données : un paiement en attente réserve sa part pendant 60 minutes, ce qui empêche deux dons simultanés de dépasser la cible. Un paiement jamais abouti libère sa part.

Mise en production : prérequis MoneyFusion

  • Renseigner MONEYFUSION_API_URL et MONEYFUSION_APP_KEY (dashboard FusionPay).
  • Autoriser l'adresse IP du serveur dans le dashboard : l'API n'est accessible que depuis les IP enregistrées.
  • Domaine HTTPS public et valide pour le retour et le webhook (APP_URL correct). En local, utiliser un tunnel.
  • Faire tourner le worker de file d'attente et le planificateur (voir section 13).
  • Faire un premier essai avec un petit montant réel : la devise et le paramètre éventuel de l'URL de retour ne sont pas précisés par la documentation MoneyFusion (l'application n'en dépend pas, elle relit toujours le statut).

Tester sans argent réel

Pour répéter le parcours sans clés, on peut pointer MONEYFUSION_API_URL et MONEYFUSION_CHECK_PAYMENT_URL vers un faux serveur local qui imite l'API (création, paiementNotif, webhook non signé). Cas à rejouer : succès avec webhook, succès sans webhook, échec, abandon, montant différent, webhook falsifié. Voir aussi les tests automatisés (tests/Feature/CagnotteTest.php, 47 tests).

Le package laravel-moneyfusion

Corrigé et testé (33 tests) dans le cadre du projet : préfixe /api réellement appliqué, statuts de l'API convertis, webhook qui relit l'API avant toute modification, contrôle d'accès par propriétaire, endpoints publics désactivables (routes.payment_endpoints), compatibilité Laravel 13. Détails dans le README.md du package.

9. Tableau de bord et exports

La page Tableau de bord (/events/{adresse}/dashboard) affiche : jours restants, invités / présents / absents / en attente, couverts attendus, taux de réponse, plan de table (par table), régimes alimentaires, état de la cagnotte et file de modération.

Règle de calcul des couverts Couverts = invités présents + leurs accompagnants. Les réponses en attente ne sont pas comptées ; les absents sont exclus du plan de table.
ExportContenuRoute
Excel3 feuilles : Invités, Régimes, Plan de table/events/{adresse}/exports/guests.xlsx
CSVListe des invités ; séparateur « ; » et BOM UTF-8 (s'ouvre directement dans Excel en français)/events/{adresse}/exports/guests.csv
PDF traiteurCouverts attendus et régimes alimentaires/events/{adresse}/exports/traiteur.pdf
PDF plan de tableInvités regroupés par table/events/{adresse}/exports/plan-de-table.pdf
Protection contre l'injection de formules Les invités saisissent eux-mêmes leur régime, leur chanson et leur message. Toute cellule commençant par =, +, - ou @ est préfixée d'une apostrophe dans les exports Excel et CSV (les numéros de téléphone internationaux +33 6 12… sont conservés). Les PDF échappent tout le contenu.

12. Sécurité

  • Accès aux données : toute action de l'hôte passe par EventPolicy (propriétaire uniquement) ; un invité ne peut agir que sur sa propre invitation (jeton de 40 caractères aléatoires) et sur les ressources de son événement.
  • Validation : chaque formulaire a sa Form Request (types, bornes, énumérations).
  • Fichiers : types vérifiés sur le contenu, taille et dimensions bornées, quotas par invité, stockage sur disque privé sous un nom aléatoire (l'extension est déduite du contenu), service par un contrôleur avec X-Content-Type-Options: nosniff ; SVG refusé.
  • Modération : rien n'est visible publiquement avant validation par l'hôte ; une photo en attente ou refusée renvoie 404 à un visiteur.
  • Paiement : jamais de crédit sans relecture serveur du statut et contrôle du montant (voir section 8) ; limite de paiements en cours par invité ; verrou sur le budget des cadeaux.
  • Exports : neutralisation de l'injection de formules (Excel/CSV), échappement dans les PDF ; PDF sans accès réseau ni PHP.
  • Limitation de débit sur toutes les routes publiques qui écrivent.
  • CSRF actif partout, sauf webhooks/moneyfusion (appelé par un serveur, sans navigateur).
  • Secrets : .env n'est pas versionné ; ne jamais committer la clé MoneyFusion.
À savoir L'inscription (/register) est ouverte : n'importe qui peut créer un compte hôte. Si ce n'est pas souhaité, restreindre ou désactiver cette route avant la mise en production.

15. Dépannage

Les invitations ne partent pas / « mise en file » mais aucun mail dans Mailpit Le worker ne tourne pas. Lancer php artisan queue:work. Vérifier aussi MAIL_PORT=1025 et que le conteneur Mailpit est démarré (docker compose ps).
« Unable to locate file in Vite manifest » Les assets ne sont pas compilés : npm run build (ou npm run dev).
« Le paiement est momentanément indisponible » MoneyFusion n'est pas configuré (MONEYFUSION_API_URL / MONEYFUSION_APP_KEY vides), l'IP du serveur n'est pas autorisée, ou l'API est injoignable. La contribution est alors marquée « Échouée ». Consulter storage/logs/laravel.log.
Un paiement reste « En attente » alors que l'invité a payé Vérifier que le worker et le planificateur tournent. php artisan contributions:reconcile revérifie immédiatement. Si MoneyFusion est injoignable ou ne connaît pas le jeton, la contribution reste en attente puis expire après 48 h.
Le webhook n'arrive jamais APP_URL doit être l'adresse publique HTTPS. En local, utiliser un tunnel. Le retour du navigateur et la réconciliation fonctionnent malgré tout.
Erreur de port 5432 / 5433 déjà utilisé Le projet utilise volontairement 5434 (développement) et 5435 (tests) pour éviter les conflits avec d'autres PostgreSQL de la machine.
Les tests échouent à la connexion à la base Démarrer le conteneur de test : docker compose up -d postgres_test. Ses données sont en mémoire : après un redémarrage du conteneur, les tables sont recréées automatiquement au prochain php artisan test.
Après modification de .env rien ne change php artisan config:clear puis redémarrer queue:work.
Le package MoneyFusion est introuvable à l'installation Le dépôt laravel-moneyfusion doit être dans ../laravel-moneyfusion. Si vous modifiez son composer.json sans nouveau commit, faire composer remove simonet85/laravel-moneyfusion puis composer require simonet85/laravel-moneyfusion:dev-main pour que Composer relise ses métadonnées.

16. Limites connues

  • Fuseau horaire : la date saisie par l'hôte est enregistrée dans le fuseau de l'application (UTC dans config/app.php), puis affichée dans le fuseau du navigateur de chaque invité. Hôte et invités dans le même fuseau que l'application (par exemple UTC+0, Abidjan) voient la même heure ; sinon un décalage apparaît. À traiter avant un usage multi-pays.
  • Modification d'un événement : l'interface permet de créer un événement et de compléter ses détails (programme, dress code, carte, cagnotte) ; il n'y a pas encore d'écran pour modifier le titre, la date ou le thème, ni pour supprimer un événement.
  • RSVP après la date : un invité peut encore répondre après la date de l'événement.
  • Devise : le FCFA est supposé (la documentation MoneyFusion ne précise pas la devise).
  • Stockage des photos : disque local privé ; pour plusieurs serveurs, prévoir un disque partagé ou un stockage objet.
  • Paiement réel non testé : validé avec un faux serveur et des tests automatisés, pas encore avec de vraies clés MoneyFusion.
  • Langue : interface en français ; pas de traduction multilingue.
